# 评分体系

## 通用评分规则

1. **第 1 轮评分上限 7 分** — 首版一定有改进空间
2. **按维度扣分** — 禁止"感觉不错，8 分"这种笼统评分
3. **最大问题必须来自最低分维度**（或并列最低）
4. **不能连续 2 轮只改同一维度** — 防止偏科
5. **高分维度不能掩盖低分维度** — 整体 8 分但正确性 4 分 = 不合格
6. **自评分仅供参考** — 不能作为终止依据（R3）

## Analyzer 模块评分

适用于 `src/analyzer/*.js`（tokenizer、classifier、annotator、phrase-extractor、risk-detector）

| 维度 | 权重 | 检查点 |
|------|------|--------|
| **正确性** | 30% | 检测准确率、误报率、边界用例处理 |
| **集成性** | 25% | 与 tokenizer 管道配合、composable 契约、import 不断裂 |
| **健壮性** | 20% | 空输入/畸形输入、CJK 文本、中英混合内容 |
| **代码质量** | 15% | DRY、函数命名清晰、与现有模块风格一致 |
| **性能** | 10% | 无冗余正则重编译、合理使用 Set/Map、万字级 listing 不卡顿 |

**评分模板：**

```
评分: X.X/10
- 正确性 (x/3.0): [具体扣分点]
- 集成性 (x/2.5): [具体扣分点]
- 健壮性 (x/2.0): [具体扣分点]
- 代码质量 (x/1.5): [具体扣分点]
- 性能 (x/1.0): [具体扣分点]
```

## Vue 组件评分

适用于 `src/components/*.vue`

| 维度 | 权重 | 检查点 |
|------|------|--------|
| **正确性** | 25% | 渲染预期输出、props/events 契约正确 |
| **视觉还原** | 25% | 遵循 linear-* token、玻璃态卡片、亮暗主题兼容 |
| **集成性** | 20% | props/events 与父组件对接、composable 用法正确 |
| **健壮性** | 15% | 处理空数据/缺失数据、加载状态、错误边界 |
| **代码质量** | 15% | SFC 顺序正确、ref 不用 reactive、handle* 命名 |

**评分模板：**

```

- 视觉还原 (x/2.5): [具体扣分点]
- 集成性 (x/2.0): [具体扣分点]
- 健壮性 (x/1.5): [具体扣分点]
- 代码质量 (x/1.5): [具体扣分点]
```

## Composable 评分

适用于 `src/composables/*.js`

| 维度 | 权重 | 检查点 |
|------|------|--------|
| **正确性** | 30% | 返回值行为符合预期、响应式状态正确更新 |
| **API 设计** | 25% | 返回接口干净、与现有 composable 风格一致 |
| **健壮性** | 20% | 边界处理、卸载时清理（如 interval/listener） |
| **集成性** | 15% | 被消费的组件能正常工作 |
| **代码质量** | 10% | 遵循 Vue 3 Composition API 模式、用 ref 不用 reactive |

**评分模板：**

```
评分: X.X/10
- 正确性 (x/3.0): [具体扣分点]
- API 设计 (x/2.5): [具体扣分点]
- 健壮性 (x/2.0): [具体扣分点]
- 集成性 (x/1.5): [具体扣分点]
- 代码质量 (x/1.0): [具体扣分点]
```

## 通用模块评分

适用于不属于上述三类的文件（如 `src/data/*.json`、`src/utils/*.js`、配置文件等）

| 维度 | 权重 | 检查点 |
|------|------|--------|
| **正确性** | 35% | 数据/逻辑正确、符合预期格式 |
| **集成性** | 25% | 被引用方能正常消费、不破坏现有流程 |
| **健壮性** | 20% | 数据完整性、格式一致性 |
| **可维护性** | 20% | 结构清晰、易于后续扩展 |

---

## 选择评分体系

根据本轮修改的主要文件类型选择对应体系。如果一轮改动跨越多种类型，以核心改动所在的文件类型为准。
