# program.md — 3 步工作流

Agent 读此文件即可执行。规则详见 **[docs/rules.md](docs/rules.md)**，评分详见 **[docs/scoring.md](docs/scoring.md)**。

---

## Step 1: 范围锁定

**任何触发本 Skill 的任务都必须先完成此步。**

在对话中输出以下结构化块：

```
## 范围锁定

- **目标**: [一句话描述要做什么]
- **影响文件**: [列出将修改的文件路径]
- **成功标准**:
  1. [可测试条件，如：npm run build 通过]
  2. [可测试条件，如：node test/verify-10cases.mjs 通过]
  3. [可测试条件，如：具体的功能行为描述]
- **回归守护**: [现有哪些功能不能被破坏]
- **复杂度**: MULTI-APPROACH / SINGLE-PASS
```

### 复杂度判定标准

**MULTI-APPROACH** — 需要进入 Step 2：
- 新建模块/组件（如新增一个 analyzer）
- 架构层面的调整（如改变数据流、管道结构）
- 涉及 3+ 文件的重构
- 存在多种合理实现路径且各有取舍

**SINGLE-PASS** — 跳过 Step 2，直接 Step 3：
- 虽然触发了 Skill 但实现路径明确
- 只需在现有模块上扩展
- 改动范围可控，无架构决策

## Step 2: 方案探索（仅 MULTI-APPROACH）

生成 2-3 个实现策略，**每个策略只写描述（5-10 行），不写代码**。

```
## 方案探索

### 方案 A: [名称]
- **策略**: [怎么实现]
- **优势**: [1-2 点]
- **劣势**: [1-2 点]
- **影响文件**: [列出]

### 方案 B: [名称]
- **策略**: [怎么实现]
- **优势**: [1-2 点]
- **劣势**: [1-2 点]
- **影响文件**: [列出]

### 选择: 方案 [X]
- **理由**: [为什么选这个，引用成功标准]
```

### 一致性检查

所有方案必须：
- 解决同一个问题（Step 1 的目标）
- 满足同样的成功标准
- 在现有架构内工作（不引入方案独有的额外依赖）

不一致则修正方案后重新对比。

---

## Step 3: 迭代精炼

在项目文件上直接实现。每轮一个聚焦改动。

### 每轮流程

```
1. 明确本轮要解决的问题（从最低分维度找）
2. 做一个聚焦改动（一处，不是三处）
3. 跑验证：构建 / 测试 / 功能检查
4. 按维度打分（见 docs/scoring.md）
5. 分数涨了 → 保留；跌了 → 回滚
6. 输出本轮小结
```

### 每轮小结格式

```
### 迭代 N

- **改动前**: 最大问题是 [X]，当前分 Y.Y
- **本轮改动**: [一句话描述]
- **验证结果**: [构建/测试结果]
- **改动后**: 分数 Z.Z（Δ +/-W.W）
- **决策**: 保留 / 回滚
```

### 终止条件

1. **主终止** — Step 1 的成功标准全部满足 → 完成
2. **上限** — 4 轮仍未全部满足 → 报告剩余问题，询问用户下一步
3. **禁止** — 仅凭"自评高分"终止（R3）

### commit 规范

每轮迭代完成后 commit（如用户允许）：

```
refine(N): [改动描述] [score: X.X → Y.Y]
```
