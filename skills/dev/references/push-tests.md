# push 前置测试 — 详细规则

> 本文件被 `/dev` 主 SKILL.md 的「push 前置测试」章节按需加载。
> 主 SKILL.md 只保留触发时机、执行条件矩阵和总输出格式；详细测试规则在本文。

## 第4项：E2E 用户场景测试（半持久，Playwright）

### 前置检查

1. 检测 Playwright 是否安装：`npx playwright --version`
   - 未安装 → 输出："需要安装 Playwright 才能执行 E2E 测试。执行 `npx playwright install --with-deps`？"
   - 用户拒绝 → 跳过 E2E，输出 `[跳过] E2E 测试未执行（无 Playwright）`
2. 检测 dev server 状态：
   - 已运行 → 直接使用
   - 未运行 → 自动启动（`npm run dev`），测试完后关闭
   - 启动失败 → 跳过 E2E，输出 `[跳过] E2E 测试未执行（dev server 启动失败）`

### 测试文件管理

| 条件 | 策略 |
|------|------|
| 文件位置 | `.skills/{product}/tests/e2e/` |
| 测试文件已存在 & 对应页面未改动 | 直接跑（复用） |
| 对应页面有改动 | 重新生成该页面的测试 |
| 新页面（无对应测试文件） | 生成新测试文件 |
| `.skills/{product}/tests/e2e/` 不存在 | 创建目录，全部新生成 |

### 测试场景自动生成（基于路由配置 + 页面组件分析）

**正常流程**：
- 核心业务路径走通（登录→主要操作→结果确认）
- 页面间导航正确（前进/后退/侧边栏切换）
- 表单提交→成功反馈→数据持久化

**极端操作**：

| 测试场景 | 验证预期 |
|---------|---------|
| 表单快速重复提交（1秒内点击3次） | 只有第1次提交生效，后续被拦截 |
| 输入框粘贴超长文本（10000字符） | 有 maxlength 截断或前端提示 |
| 输入 XSS payload（`<script>alert(1)</script>`） | 被转义显示，不执行脚本 |
| 浏览器后退键（提交成功后回退） | 不会重复提交，页面状态正确 |
| 页面中途刷新（操作到一半 F5） | 无白屏/报错，数据不丢失或有恢复提示 |

**异常状态**：

| 测试场景 | 验证预期 |
|---------|---------|
| 未登录访问需鉴权页面 | 跳转到登录页 |
| 直接输入不存在的路由 | 显示 404 页面 |
| Token 过期后操作 | 合理提示并跳转登录 |

### E2E 测试输出

```
[E2E] 用户场景测试 — N 个场景

  ✓ 登录→首页：正常
  ✓ 表单提交→成功反馈：正常
  ✗ 表单重复提交：第2次提交未被拦截
  ✗ XSS 输入：<script> 标签未被转义
  ✓ 未登录访问 /dashboard：正确跳转登录页
  — 404 页面：跳过（无 404 路由配置）

通过：4/6 | 失败：2 | 跳过：1
```

## 第5项：API 安全测试（临时生成，node 脚本执行）

**前置条件**：需要 dev server / 后端服务在运行。无服务运行时 → 跳过，输出 `[跳过] API 安全测试未执行（后端未启动）`

### 执行步骤

1. `Grep` 搜索项目中的 API 端点定义（路由文件、FastAPI 路由装饰器、Express router）
2. 提取端点列表（方法 + 路径 + 是否需鉴权）
3. 针对每个端点生成临时测试脚本（node 脚本，使用 `fetch`）
4. 执行脚本，收集响应状态码和内容
5. 对比预期行为，标记 PASS/FAIL
6. 删除临时脚本

### 测试项

| 测试类别 | 具体测试 | 预期结果 |
|---------|---------|---------|
| **认证绕过** | 不带 Token 访问需鉴权接口 | 返回 401 |
| | 带过期/伪造 Token 访问 | 返回 401 |
| | 带其他用户 Token 访问非自己的资源 | 返回 403 |
| **注入攻击** | SQL 注入 payload：`' OR '1'='1`、`1; DROP TABLE users--` | 不返回异常数据，不报 500 |
| | XSS payload：`<script>alert(1)</script>` | 被过滤/转义 |
| | 路径遍历：`../../etc/passwd` | 返回 400 或被拦截 |
| **参数篡改** | 修改请求中的 userId/权限字段为其他值 | 返回 403 或忽略篡改 |
| | 数值参数改为负数/极大值 | 有参数校验，不导致异常 |
| | 额外字段注入（`__proto__`、`constructor`） | 被忽略或拦截 |
| **过载防御** | 超大 body（描述 >10MB 场景） | 有 body 大小限制 |
| | 超长字符串字段 | 有字段长度限制 |

### API 安全测试输出

```
[API 安全] N 个端点 × M 项检查

  POST /api/auth/login
    ✓ 无 Token：返回 401
    ✓ SQL 注入：返回 400
    ✗ 超长密码字段：无长度限制，接受了 10000 字符

  GET /api/users/:id
    ✗ 无 Token：返回 200（应为 401）
    ✗ 他人 Token：返回 200（应为 403）

通过：3/8 | 失败：3 | 跳过：2
```

## 第6项：极端环境检查（静态扫描）

**不执行代码**，通过 `Grep` + `Read` 扫描改动文件中是否有对应的防御机制。

### 网络异常防御

| 检查项 | 检查方式 | 严重级别 |
|-------|---------|---------|
| API 调用无 timeout | `Grep` 搜索 `fetch(`/`axios` 调用，检查是否有 timeout 配置 | 中等 |
| 网络错误无用户提示 | `Grep` 搜索 `catch` 块，检查是否有用户可见的错误提示 | 中等 |
| 无请求重试机制 | `Grep` 搜索是否有 retry/重试逻辑 | 建议 |

### 并发防御

| 检查项 | 检查方式 | 严重级别 |
|-------|---------|---------|
| 提交按钮无防重复 | `Grep` 搜索 `@click="handle` 的按钮，检查是否有 `:disabled="isLoading"` 或类似机制 | 中等 |
| 高频操作无节流 | `Grep` 搜索 `@input`/`@keyup` 绑定，检查是否有 `debounce`/`throttle` | 建议 |

### 存储防御

| 检查项 | 检查方式 | 严重级别 |
|-------|---------|---------|
| localStorage 操作无异常处理 | `Grep` 搜索 `localStorage.`/`sessionStorage.`，检查是否被 `try-catch` 包裹 | 中等 |

### 大数据量防御

| 检查项 | 检查方式 | 严重级别 |
|-------|---------|---------|
| 列表无分页/虚拟滚动 | `Grep` 搜索 `v-for`，检查数据源是否有分页逻辑或虚拟滚动组件 | 建议 |
| 图片无懒加载 | `Grep` 搜索 `<img`，检查是否有 `loading="lazy"` 或 `v-lazy` | 建议 |

### Token/鉴权防御

| 检查项 | 检查方式 | 严重级别 |
|-------|---------|---------|
| 无 Token 过期处理 | `Grep` 搜索 Token 相关代码，检查是否有过期检测和刷新/跳转逻辑 | 严重 |
| 路由守卫不完整 | `Grep` 搜索 `router.beforeEach`，对比路由配置中需鉴权的页面是否全部被守卫覆盖 | 严重 |

### 极端环境检查输出

```
[极端环境] 防御机制检查 — N 项

  网络异常防御：
    ✗ [中等] 3 个 fetch 调用无 timeout — src/api/user.js:12, src/api/order.js:8, src/api/data.js:15
    ✓ 网络错误有 catch 和用户提示
  并发防御：
    ✗ [中等] 2 个提交按钮无防重复 — Form.vue:45, EditModal.vue:23
  Token/鉴权防御：
    ✓ 有 Token 刷新逻辑
    ✗ [严重] 路由守卫未覆盖 /settings 页面

通过：4/8 | 失败：4
```
