# /guard — 偏离日志与 Override 管理

## 定位

`/guard` 是一个**手动辅助工具**，用于查看偏离日志和管理强制跳过。

偏离的**检测**不在这里 — 检测逻辑内置在以下位置：
- `/dev`：编码过程中自行对照验收标准，检测功能蔓延和实现偏差
- `/dev check`：完整的 PRD + baseline 四类偏离检测
- `/dev done`：第1关+第2关自动包含偏离检查
- `/req update`：三层偏差检测（baseline / PRD / 历史继承）

`/guard` 只负责**日志查看**和**强制跳过记录**。

### 典型衔接场景

| 来源 | 场景 | 用户接下来做什么 |
|------|------|-----------------|
| `/dev check` 检测到偏离 | 想看历史偏离是否有规律 | → `/guard status` 或 `/guard report` |
| `/dev` 编码中弹出偏离警告 | 确认偏离但有正当理由要继续 | → `/guard override [理由]` |
| `/review` 发现多次偏离 | 想看完整偏离时间线 | → `/guard report` |
| 累计 override ≥ 3 次 | guard 自动提醒 | → `/req update` 重新评估需求 |

## 前置检查（每次执行前必须完成）

### 1. 获取当前产品

读取 `.skills/context.json`，取 `activeProduct` 字段作为 `{product}` 变量：

- 若文件不存在或 `activeProduct` 为空：
  - 如果操作员在命令中指定了产品名（如 `/guard status --product xxx`）→ 使用指定的产品名继续
  - 否则 → 输出提示并终止：

```
未找到 .skills/context.json，无法确定当前产品。
请先通过 /req 初始化产品，或指定产品名：/guard status --product [产品名]
```

### 2. 检查 guard log 是否存在

读取 `.skills/guard/{product}.log`：

- 若文件不存在，不报错，后续命令输出"暂无偏离记录"即可，不终止执行。

## 子命令路由

| 参数 | 执行 |
|------|------|
| `status` | → 查看累计偏离记录概要 |
| `report` | → 生成完整偏离报告 |
| `override [理由]` | → 记录一次强制跳过偏离的决定 |
| 无参数 | → 显示偏离概要 |

### 自然语言路由

当操作员使用自然语言而非精确命令时，按以下规则映射：

| 操作员可能的表达 | 映射到 |
|---|---|
| "偏离了多少"、"看看偏离" | → status |
| "详细偏离报告" | → report |
| "这个偏离我知道，跳过" | → override |

## status — 偏离概要

### 解析逻辑

读取 `.skills/guard/{product}.log`，逐行解析：

1. **行格式匹配**：每条记录以 `[YYYY-MM-DD HH:MM]` 开头，后跟 `[类型] | [REQ-ID] | [严重程度]`
   - 匹配正则：`^\[(\d{4}-\d{2}-\d{2} \d{2}:\d{2})\] (\w+) \| (REQ-[\w-]+) \| (.+)$`
   - 不匹配的行：跳过，但计入 `skipped_lines` 计数器
   - 续行（以 `  描述：`、`  处理：`、`  理由：` 开头）：归属到前一条记录
2. **分类统计**：按类型字段分组计数
   - `SCOPE_CREEP` → 功能蔓延
   - `IMPL_DRIFT` → 实现偏差
   - `MISSING_REQ` → 需求遗漏
   - `DIRECTION_DRIFT` → 方向偏离
   - `OVERRIDE` → 强制跳过（单独统计）
   - 未知类型 → 归入「其他」，输出时标注类型原文
3. **排序**：按时间倒序，最近一次偏离取第一条非 OVERRIDE 记录
4. **容错**：如果 skipped_lines > 0，在输出末尾追加警告

### 输出格式

```
[GUARD STATUS]

产品：[产品名]
累计偏离记录：N 条
  功能蔓延：X 条
  实现偏差：Y 条
  需求遗漏：Z 条
  方向偏离：W 条

累计强制跳过：M 条
最近一次偏离：[时间] [类型] [描述]
```

如有解析异常行：
```
⚠ 日志中有 K 行格式不匹配，已跳过。可能是日志写入不完整或格式变更，建议检查 .skills/guard/{product}.log
```

## report — 完整偏离报告

### 解析与排序

使用与 status 相同的解析逻辑（正则匹配 + 续行归属 + 格式异常跳过），按**时间正序**输出全部记录（最早的在前，方便阅读偏离演变过程）。

### 输出格式

```
[GUARD REPORT] 完整偏离报告

产品：[产品名] | 记录数：N 条

[1] [时间] SCOPE_CREEP | REQ-A-001 | 严重
    描述：[偏离内容]
    处理：已中断，回到原任务

[2] [时间] IMPL_DRIFT | REQ-B-003 | 中等
    描述：[偏离内容]
    处理：已修正

[3] [时间] SCOPE_CREEP | REQ-A-002 | 低
    描述：[偏离内容]
    处理：强制跳过
    理由：[操作员给出的理由]
```

如有解析异常行，在报告末尾追加与 status 相同的警告。

记录数为 0 时输出：
```
[GUARD REPORT] 暂无偏离记录

产品：[产品名]
当前无任何偏离记录。继续保持 👍
```

## override — 强制继续

`/guard override [理由]`

当操作员明确知道在偏离但有正当理由时使用。

**执行步骤**：
1. 理由不能为空，如果为空则要求补充
2. 对理由进行质量校验（见下方规则），不通过则拒绝记录并要求重新填写
3. 记录到 `.skills/guard/{product}.log`
4. 写入日志成功后，统计当前产品的累计 override 次数 N；若 N ≥ 3，额外输出升级提醒：

```
[GUARD] ⚠ 累计强制跳过已达 {N} 次

频繁跳过可能意味着需求本身需要调整。建议：
1. 执行 /req update 重新评估受影响的需求条目
2. 执行 /req baseline --drift-summary 检查渐进偏差
3. 如果偏离是合理的业务调整，通过 /req update 正式纳入 PRD

→ 是否现在执行 /req update？
```

**理由质量校验规则**：

| 规则 | 说明 |
|------|------|
| 长度 ≥ 10 字 | 理由过短无法说明问题，必须补充 |
| 不能是纯压力性理由 | 仅含"赶时间"、"来不及"、"先跳过"、"没时间"等词且无其他内容时，拒绝 |
| 必须包含具体原因 | 说明为什么这次偏离是可接受的 |
| 必须包含后续计划 | 说明后续如何补救或跟进 |

校验不通过时的提示示例：

```
理由质量不足，无法记录强制跳过。

问题：[具体问题，如"理由少于10字" / "仅含压力性描述，缺少具体原因和后续计划"]

请补充：
  1. 具体原因：为什么这次偏离是可接受的？
  2. 后续计划：后续如何补救或跟进？

示例（合格）：
  "该需求与本期核心路径无关，优先级低；已在 PRD 中标注为 v2 待办，下期迭代补充。"
```

**记录格式**：
```
[YYYY-MM-DD HH:MM] OVERRIDE | REQ-[ID] | [理由]
```

---

## 日志文件格式

`.skills/guard/{product}.log` 由 `/dev` 编码过程中自动写入，`/guard` 负责读取和追加 强制跳过：

```
[YYYY-MM-DD HH:MM] [类型] | [REQ-ID] | [严重程度]
  描述：[偏离内容]
  处理：[已中断/已修正/强制跳过]
  理由：[仅强制跳过时有此字段]
```

类型取值：`SCOPE_CREEP` | `IMPL_DRIFT` | `MISSING_REQ` | `DIRECTION_DRIFT` | `OVERRIDE`

## 无参数时（`/guard`）

```
产品：[产品名]
累计偏离：N 条 | 强制跳过：M 条

命令：
  /guard status     — 偏离概要
  /guard report     — 完整偏离报告
  /guard override   — 记录一次强制跳过（需给理由）

override 理由要求：≥10字、说明具体原因和后续计划、不能是纯压力性理由（如"赶时间"、"先跳过"）
```
